# V6b：把 V5 的 P 重排成 R，并独立验证

## 1. 做什么

输入 P `[K/8,N]` 是沿 K 打包的 uint32；输出 R `[K/16,ceil(N/8),16]` 是 V6a 定义的 tile-major 形式。一次重排是**准备阶段**，不是每轮 K 循环都运行。Z/S 不参与该 kernel，保持原来的布局。

```text
CPU 测试先创建逻辑 Q → 构建原 P → GPU repack → R
       │                                       │
       └────────── CPU 从 Q 独立构造期望 R ──────┘
```

只做 `pack→unpack` 往返容易让两边相同的错误互相抵消；这里 CPU 直接读取逻辑 Q，按图构造期望 word，再逐 nibble 检查真实列和末 tile 的补零。

## 2. 每个线程负责什么

launch 使用一维 block 256 线程，输出的每个 **R word** 由一个线程独占写入；K 是 128 的倍数，N 正数。令 `nt=ceil(N/8)`：

```text
R 的线性数组： [ktile 0, ntile 0, kin 0..15]
              [ktile 0, ntile 1, kin 0..15] ...

thread i=0..15    → ktile=0, ntile=0, kin=0..15
thread i=16..31   → ktile=0, ntile=1, kin=0..15（若 nt≥2）
```

因此：先看每个 K tile 有多少个输出 word，再用除法/取余拆解 `i`；得到 `k=16*ktile+kin`。对于一条线程，对 j=0..7：

```text
n=8*ntile+j
如果 n<N：从 P[k/8,n] 中提取第 k%8 个 nibble
            放到结果 word 的第 j 个 nibble
否则：该 nibble 为 0，不读 P
最后一次写 R[i]
```

手算：N=9、`i=16` 时，`ktile=0,ntile=1,kin=0`，即 k=0、目标列 n=8..15；只有 n=8 有效。假设 Q[0,8]=10，则 word 为 `0x0000000a`。所有其他 nibble 是 0，即使越界 P 后面在物理上还有其他行，也不能读取。

```bash
cp kernels/marlin_from_scratch/v6b_repack_template.cu kernels/marlin_from_scratch/v6b_repack.cu
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo \

CUDA_VISIBLE_DEVICES=1 /tmp/quant_v6b
```
