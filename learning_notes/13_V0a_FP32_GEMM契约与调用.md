# V0a：FP32 GEMM 的契约与调用

本节只学习输入输出和调用，不单独写 kernel。V0a、V0b、V0c 共用 [V0 练习模板](../kernels/marlin_from_scratch/v0_gemm_template.cu)；你将在 V0b 中填写 kernel，V0c 则理解并使用已准备的计时框架。

## 1. 要解决什么问题

计算普通 FP32 矩阵乘，为之后实现量化 GEMM 建立一个最简单的对照：

```text
A [M,K] × B [K,N] = C [M,N]
C[row,col] = Σ(p=0..K-1) A[row,p] × B[p,col]
```

这里是浮点 B，不是后续的 4-bit Q；本节没有 pack、scale、zero、bias、padding 或 Tensor Core。V0 的 CPU 参考测试使用小整数形式的 FP32 数值。

```text
              K                          N
         ┌────────┐                ┌──────────┐
     M   │   A    │       ×     K  │    B     │
         └────────┘                └──────────┘
                                  ↓
                         ┌──────────┐
                     M   │    C     │
                         └──────────┘
                              N
```

## 2. 输入输出契约

| 项目 | 本练习约定 |
|---|---|
| A / B / C | 同一 GPU 可访问的 `float` 设备数组；本模板使用 `cudaMalloc` |
| 形状 | A `[M,K]`、B `[K,N]`、C `[M,N]`；`M,N,K` 为正 |
| 布局 | 三者均按行连续：最后一维的相邻元素在内存中相邻 |
| 输出 | 每个有效 `C[row,col]` 完全覆盖写入一次，不读取旧 C；无 bias |
| 数值 | 输入、线程累加器和输出均为 FP32；与未来 W4A16 的 BF16 契约不同 |
| 范围 | 本程序的形状和整数索引限于模板测试的可表示范围；不支持带任意 stride 的 view |
| 别名 | A、B、C 使用独立存储；不承诺输入输出重叠时正确 |
| 执行 | 模板单 GPU、默认 stream；不承诺任意 stream、并发或多设备接口 |

这是一份**练习调用契约**，不是已经实现了面向任意调用者的通用输入校验。模板自身创建满足约定的输入，暂时不提供任意形状/指针的外部 API，也没有对不符合约定的输入逐项报错。

行优先时，逻辑坐标变成线性**元素索引**的方法是：

```text
A[row,p] → a[row*K + p]
B[p,col] → b[p*N + col]
C[row,col] → c[row*N + col]
```

这里的 `row*K+p` 是第几个 `float`，不是字节地址。C++ 的 `a[index]` 会按元素类型计算地址；分配和复制时才用 `元素数 * sizeof(float)` 计算字节数。

## 3. 手算一个完整例子

固定一个能在纸上验算的例子：`M=2,K=3,N=2`。

```text
       A [2,3]            B [3,2]            C [2,2]
     ┌         ┐        ┌     ┐            ┌       ┐
     │ 1  2  3 │        │ 1  0│            │ 4   5 │
     │ 4  5  6 │   ×    │ 0  1│        =   │10  11 │
     └         ┘        │ 1  1│            └       ┘
                        └     ┘

C[0,0] = 1×1 + 2×0 + 3×1 = 4
C[1,1] = 4×0 + 5×1 + 6×1 = 11
```

例如计算 C[1,1] 时，A 的元素索引依次为 `3、4、5`；B 的元素索引依次为 `1、3、5`；输出 C[1,1] 的元素索引是 `1*2+1=3`。这是手算示意；模板自动生成的数值使用固定规则，并不恰好是上面的 A/B。

## 4. 一次调用的 CPU/GPU 数据流

```text
CPU / host                              GPU / device
准备 h_a、h_b             ──复制──→     d_a、d_b：global memory
准备 C 的哨兵值           ──复制──→     d_c：global memory
发射 v0_gemm<<<grid,block>>> ──────→     block → warp → thread
                                         每线程算一个输出元素
检查发射；等待执行完成     ←────────     计算完成，结果写到 d_c
复制结果、逐元素检查       ←──复制──     d_c
```

模板的 `CUDA_CHECK` 检查每个 CUDA API；`cudaGetLastError()` 检查发射状态，`cudaDeviceSynchronize()` 等待设备上先前工作并检查错误。读取结果后用独立 CPU 三重循环比较；即使 API 没报错，也不能省略数学结果检查。
