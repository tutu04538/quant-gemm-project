# V1b：shared tile 的边界与同步

这一节与 V1a 使用同一个 [V1 模板](../kernels/marlin_from_scratch/v1_gemm_template.cu)，不新增模板。目标是理解尾部填零和两次同步为什么都需要。

## 1. 三个方向都可能越界

以 `M=17,N=19,K=23`、tile=16 为例，grid 是 `(2,2)`，一共 4 个 block。K 分两轮：第一轮 `base=0`，第二轮 `base=16`。

```text
输出 C [17,19]：
             N 0～15       N 16～18     N 19～31
           ┌───────────┬───────────┬──────────────┐
M 0～15    │ 全有效    │ 3 列有效  │ 输出越界     │
           ├───────────┼───────────┼──────────────┤
M 16       │ 1 行有效  │ 1×3 有效  │ 输出越界     │
M 17～31   │ 输出越界  │ 输出越界  │ 输出越界     │
           └───────────┴───────────┴──────────────┘

K 第二轮：base=16，局部 p=0～6 对应 K=16～22 有效；p=7～15 越界。
```

block 内 256 个线程始终按原 block 配置运行；在任何一轮中，无法合法读取的 A/B 位置必须写 0 到对应 shared 元素。每个输出有效线程都应累加到正确的 sum，最后只写有效 C。

## 2. 输出越界的线程也可能需要工作

看 `M=1,N=1,K=3` 的 block 0：thread `(tx=0,ty=1)` 的输出行 `row=1` 无效，不能写 C[1,0]。但如果按 V1a 的协作加载，它还要为其他线程加载 `B[base+1,0]` 到 `bs[1,0]`；计算 C[0,0] 的 thread 需要这个值。

```text
thread (0,1)：输出 row=1 越界，但 B[1,0] 有效
       │ 写入
       ▼
    bs[1,0] ──同步后──→ thread (0,0) 用它计算 C[0,0]
```

因此不能像 V0 那样在 kernel 开头对输出越界线程直接 `return`。本实现让所有线程参加每轮 shared 填充和两个同步点，最后只对有效输出写 global C。

## 3. 为什么有两次同步

```text
一轮 K tile：

线程合作写 as / bs
        ↓
同步 ①：等待写入完成，之后才能读取其他线程写的值
        ↓
线程读取 shared、累加各自 sum
        ↓
同步 ②：等待读取完成，之后才能覆盖 shared 进入下一轮
        ↓
下一轮写 as / bs
```

`__syncthreads()` 是 block 内屏障，不同步其他 block。两处屏障都需让 block 内相关线程以一致控制流到达；不要把它们放进只对有效输出线程成立的条件。

只执行同步 ① 不够：某些线程可能已完成本轮读取，准备把下一轮数据写入 shared，另一些线程却还在读本轮数据。同步 ② 防止这种覆盖。最后一轮之后虽不再复用，本模板要求每轮统一执行同步 ②，便于保证循环的协议清楚。

## 4. 编译和正确性检查

假设你已复制模板并写入 `v1_gemm.cu`：

```bash
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo \
    kernels/marlin_from_scratch/v1_gemm.cu -o /tmp/quant_gemm_v1
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_gemm_v1
```

GPU 1 只是示例，运行前检查是否空闲。`-lineinfo` 保留工具定位源码行所需的信息，不等于开启完整调试构建；实际工具和权限要以当时检查为准。

模板覆盖 `(M,N,K)=(2,2,3)、(1,1,1)、(5,7,9)、(17,19,23)、(31,33,33)、(16,128,256)`，其中 K=33 跨 3 轮。与 V0 一样，模板数值是小整数，所列 case 的运算可由 FP32 精确表示，所以采用精确比较；一般浮点输入需另定容差。

普通测试通过只说明这些输入的输出正确，不自动证明所有线程交互没有竞争。你写完后我会结合源码检查，并在可用环境下运行 `compute-sanitizer` 的 memcheck、racecheck、synccheck；无法运行时说明限制。
