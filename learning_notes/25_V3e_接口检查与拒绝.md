# V3e：受限接口、参数检查与拒绝

## 1. 目标

V3c/d 的 GPU kernel 假设调用者给出的地址、形状、布局都正确；错误参数可能导致越界或得到错误结果。V3e 增加一个教学用 host 入口，在发射之前检查它能够检查的条件；如果输入不符合约定，返回明确状态，避免启动 GEMM。

代码为 [v3e_checked.cu](../kernels/marlin_from_scratch/v3e_checked.cu)，直接调用你写在 `v3_w4a16_template.cu` 中的 `w4a16_gemm`，没有更改你的 kernel。为了复用当前单文件练习，它用 `#define main ...` 临时给原测试入口改名后 include；这是一种教学复用方式，不是推荐的长期库组织。将来可以把 kernel、声明和测试拆成单独文件。

## 2. 调用路径与责任

```text
host：Matrix A/P/Z/S/C（地址 + dtype 声明 + 行列 + 行步长）
           │
           ├─ 正尺寸、K 能被 128 整除、整数下标和 grid 范围
           ├─ shape、声明 dtype、连续行步长、非空和对齐
           ├─ 地址属于当前 GPU 的 device allocation，检查剩余容量
           ├─ 各矩阵实际使用的地址区间互不重叠
           ├─ 同步，复制 Z/S 到 host，检查 zero 和 scale 的值
           │
      不符合 → 返回状态，不发射 GEMM
           │
        符合 → 默认 stream 发射 w4a16_gemm
                      │
GPU：      block (16,16)，每条有效线程计算一个 C 元素
                      │  读取 A、P、Z、S，按 K 循环
                      ↓
host：检查 launch，再等待设备完成；成功才返回 OK
```

GPU 中 block、warp、lane、packed 位序与 [V3 笔记](24_V3_W4A16.md) 完全相同。检查入口不改变权重布局或 BF16 舍入约定。

## 3. 具体检查了什么

`Matrix` 的 `row_stride` 单位是元素，不是字节。这里要求 stride 等于列数，例如 BF16 A `[3,256]` 的行步长为 256，第二行起始位置距第一行是 256 个 BF16，即 512 字节。传入 257 会返回 `STRIDE`，而不是悄悄按连续数组计算。

| 条件 | 处理 |
|---|---|
| M/N/K 非正、K 不整除 128、shape 不匹配、索引或 grid 超限 | `SHAPE` |
| 声明的 dtype 不匹配 | `TYPE` |
| 行步长不是连续布局 | `STRIDE` |
| 空、未对齐、host 或不支持的设备指针 | `POINTER` |
| 指针位于其他 GPU，或设备不满足 SM 8+ | `DEVICE` |
| 数组从指针位置到分配末尾不足以容纳需要的字节数 | `CAPACITY` |
| 任意两个矩阵实际访问的地址区间重叠 | `ALIAS` |
| Z 存在大于 15 的值 | `ZERO` |
| S 包含负数、NaN 或无穷 | `SCALE` |
| CUDA 操作或 kernel 执行报告错误 | `CUDA_ERROR` |
| 全部检查并完成 GPU 运算 | `OK` |

Q 已打包为 uint32，一个 nibble 自然只能表示 0～15；Z 以 uint8 保存，所以必须额外检查是否超出 15。为简化契约，这个版本允许 scale 为 0，拒绝负数和非有限数。

例如一个 CUDA 分配起始地址是 1000、大小是 100 字节，调用者给的指针为 1020：从该指针起最多剩余 80 字节；若矩阵需要 84 字节，就返回 `CAPACITY`。实际程序用 CUDA Driver API 的 `cuMemGetAddressRange` 获取分配范围，`cudaPointerGetAttributes` 获取设备和指针类型；`-lcuda` 用于链接 Driver API。地址区间检测使用半开区间 `[begin,end)`：结尾恰好等于另一区间开头不算重叠。

## 4. 这个接口的边界

- 只接收当前设备上普通 `cudaMalloc` 的设备分配；不支持 managed、host、其他设备、显存池等未声明的分配方式。不同分配 API 的地址范围行为不能一概假定。
- 指针本身没有 dtype 信息。程序只能验证调用者的 `dtype` 声明，无法识别一片字节真实原来是什么类型，也无法证明输入数据语义正确。不会扫描 A 中是否存在 NaN/Inf，也不对这些值的数值行为作保证。
- 调用者保证缓冲在函数调用期间保持有效，且其他线程和 stream 不并发修改、释放或读取这些缓冲。本版没有实现和测试通用并发协议。
- 不提供 stream 参数。函数会调用 `cudaDeviceSynchronize`，复制 Z/S 到 CPU 检查，并同步等待 kernel；这些步骤有显著额外成本，不可把它当成异步生产接口或拿它的端到端时间冒充裸 kernel 时间。
- 参数拒绝时不会发射 GEMM，测试验证了指定拒绝场景下 C 不变。若 CUDA 本身发生错误或 kernel 执行失败，返回 `CUDA_ERROR`，此时不保证 C 的状态。设备同步也可能观察到此前的异步错误。
- 输入输出均按 V3 契约：A/S BF16、P uint32、Z uint8、C FP32；支持 K 为正且为 128 的倍数，N 不必为 8 或 16 的倍数。BF16 主线的输出转换、padding、bias 以及更复杂的接口留给后续版本。

## 5. 测试和复现

```bash
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo \
  kernels/marlin_from_scratch/v3e_checked.cu -lcuda -o /tmp/quant_v3e_checked
nvidia-smi
CUDA_VISIBLE_DEVICES=0,1 /tmp/quant_v3e_checked
CUDA_VISIBLE_DEVICES=0,1 /usr/local/cuda-12.1/bin/compute-sanitizer \
  --tool memcheck --error-exitcode 1 /tmp/quant_v3e_checked
```

先确认所选 GPU 空闲。两个可见 GPU 用于测试拒绝其他 GPU 上的指针；若仅一个可见 GPU，该测试会明确跳过。

2026-11-22 在 RTX 4090、CUDA 12.1、`sm_89` 下：19 项返回状态检查通过，包括合法调用、不同 M 交替、重复调用、shape/stride/dtype、指针、容量、别名、zero/scale 和其他 GPU；检查了正确输出与拒绝后 C 不变。原始 V3 的六组逐权重和 GEMM 参考测试也通过，但这部分直接调用原 kernel，不经过 checked 入口。`compute-sanitizer memcheck` 报告 0 个错误。未测性能，未测试并发或非默认 stream。
