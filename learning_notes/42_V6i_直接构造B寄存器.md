# V6i：参考 Q、packed zero、scale 如何组成 MMA B fragment

## 1. 目标

本节直接使用固定实例的 Q/Z/S **参考物理布局**，按实际 block/warp/lane、step、j 得到四个 BF16x2 寄存器。参考路径为 `dequant_data → sub_zp → scale`；本实验用于观察寄存器内容，直接从 global 输入读取，未实现参考的 shared pipeline。

参考源码位置：[片段读取/解码](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/marlin_template.h#L933)、[matmul](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/marlin_template.h#L1222)、[sub_zp/scale](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/marlin_template.h#L104)。我们固定 BF16/U4、整数 zero、group 128、无 act-order，其他分支不能套用。

## 2. 具体 lane 怎样找到 Q/Z/S

```text
输入物理 Q：[16,256] uint32     物理 Z：[2,16] uint32     物理 S：[2,128] BF16
block b → nr=b/2, kr=b%2；warp w=threadIdx/32；lane l=threadIdx%32
r=l/4；step=0/1；j=0..3

Q word：Qphys[8*kr+2*w+step, 128*nr+4*l+j]
Z word：Zphys[kr, 8*nr+r]             ← 一个 uint32 包含 8 个 zero
S 值：  Sphys[kr, 64*nr+8*r+2*j] 和其后一个 BF16
```

这个实验从 global 直接读取上述同值；参考 kernel 先将数据放入 shared、再加载到 `frag_b_quant`、`frag_qzp`、`frag_s`，所以物理**存储地址**和参考线程的 shared 索引不是同一回事。

对同一个 lane，令 `n0=64*nr+16*j+r`：

```text
j         0        1         2         3
列 0   n0=r     r+16      r+32      r+48
列 1   r+8      r+24      r+40      r+56

Z word 低→高 nibble 的列：[r,r+16,r+32,r+48,r+8,r+24,r+40,r+56]
因此 j 的两列分别选 zero nibble j、j+4。
S 连续值的列： [r,r+8,r+16,r+24,r+32,r+40,r+48,r+56]
因此 j 的两列分别选 scale 位置 2j、2j+1。
```

例如 block 2（nr=1,kr=0）、warp 1、lane 5（r=1）、step 0、j=2：逻辑列是 97 和 105；取对应 Z nibble 2/6、S 元素 4/5。不要把 lane 5 的物理 Q word 列直接当作逻辑输出列。

## 3. 片段顺序与 BF16 数值

沿用 V6h 的 4 对 raw：

```text
raw0/raw1 → frag_b0 的 2 个 BF16x2 → 第一列 n0
raw2/raw3 → frag_b1 的 2 个 BF16x2 → 第二列 n0+8

128+Q ── BF16x2 减去 128+对应列 Z ──→ Q-Z
      ── BF16x2 乘对应列 BF16 scale ──→ 可供 MMA 的 BF16 对
```

假设第一列的一对 Q 是 (11,3)，Z=7，S=0.25：得到 `(1,-1)`；若第二列有不同 Z/S，要独立取第二组。乘法结果是 BF16，不能先累计成 FP32 再假装和参考路径相同。

## 4. 实践

复制 [v6i_marlin_fragments_template.cu](../kernels/marlin_from_scratch/v6i_marlin_fragments_template.cu) 为 `v6i_marlin_fragments.cu`，完成 trace kernel 的解码、配 zero/scale 与 BF16x2 操作。`v6i_lop3` 已给出，避免重复 V6h 的语法练习；保存 4 个 BF16x2 的原始位供 CPU 对照。

```bash
cp kernels/marlin_from_scratch/v6i_marlin_fragments_template.cu kernels/marlin_from_scratch/v6i_marlin_fragments.cu
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo kernels/marlin_from_scratch/v6i_marlin_fragments.cu -o /tmp/quant_v6i_marlin
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_v6i_marlin
```

host 由三个随机 seed 的逻辑 Q/Z/S 独立构造参考布局，测试覆盖所有四个 block、四 warp、32 lane、两 step、四 word，按逻辑 Q/Z/S 独立生成预期 BF16 位并逐寄存器比较。临时参考填充三组通过，三个 sanitizer 未报告错误或危害；这验证诊断 kernel，不是上游运行时真实寄存器捕获，也不是用户代码结果。
