# V6f：从逻辑 Q 到固定 Marlin 分支的 packed word

## 1. 目标与数据契约

把 standard `P[K/8,N]` 转成与参考 `gptq_marlin_repack` 的 W4、`is_a_8bit=false,has_perm=false` 分支相同的输出位序。每个 P word 沿 K 放 8 个 nibble（低位对应小 k）。仅支持 `K%16=0,N%64=0` 的正尺寸；固定例 K=256,N=128，无 padding。输出物理连续数组共有 `K*N/8` 个 uint32；参考张量外观形状 `[K/16,2N]`，对照时要以物理 word 的顺序为准。

参考 [gptq_marlin_repack.cu](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/gptq_marlin_repack.cu) 的 16×64 tile 和结果位序；我们自己的练习使用“一线程一个输出 word”的朴素算法，不复制参考的 shared/异步流水线。

## 2. tile、线程和 32 lane 图

每个逻辑 tile 是 `16 K × 64 N = 1024` 个 nibble = 128 个 uint32 word。本练习让一个 128 线程的 block 负责一个 tile：4 个真实 warp 各有 32 个 lane，每条 lane 生成一个 word。**这里真实的 warp/lane 直接对应参考 `repack_tile` 中的 `warp_id/th_id`**。

```text
blockIdx.y → K tile       blockIdx.x → N tile
threadIdx.x / 32 → warp   threadIdx.x % 32 → lane
tile 内输出 word 偏移 = lane*4 + warp

tile 内连续 word：lane0 warp0, lane0 warp1, lane0 warp2, lane0 warp3,
                 lane1 warp0, lane1 warp1, lane1 warp2, lane1 warp3, ...

lane  0.. 3：tc_col=0；k 的起点依次 0,2,4,6
lane  4.. 7：tc_col=1；k 的起点依次 0,2,4,6
lane  8..11：tc_col=2；k 的起点依次 0,2,4,6
lane 12..15：tc_col=3；k 的起点依次 0,2,4,6
lane 16..19：tc_col=4；k 的起点依次 0,2,4,6
lane 20..23：tc_col=5；k 的起点依次 0,2,4,6
lane 24..27：tc_col=6；k 的起点依次 0,2,4,6
lane 28..31：tc_col=7；k 的起点依次 0,2,4,6
warp 0/1/2/3 的 N 起点分别为 0/16/32/48（相对当前 64 列 tile）
```

例如 `threadIdx.x=1` 是 warp 0、lane 1，写 tile 内 word 4；`threadIdx.x=32` 是 warp 1、lane 0，写 tile 内 word 1。相邻线程不一定写相邻 word：这是参考输出的交错顺序。注意我们仅对齐**单 tile 内 word 的线程映射**；参考完整 repack 使用 256 线程 block、shared 和异步搬运，并由 block 处理 tile 范围，本练习用 128 线程 block 直接从 global P 读取，不能说两者完整实现或性能相同。

令 `tc_col=lane/4, tc_row=2*(lane%4)`，N 相对 tile 的起点 `warp*16+tc_col`。此 word 的 8 个 nibble，低→高：

```text
            N起点+0     N起点+8
K起点+0       nib 0       nib 2
K起点+1       nib 4       nib 6
K起点+8       nib 1       nib 3
K起点+9       nib 5       nib 7
```

其中 K 起点是 `tc_row`。例如 lane=0、warp=0：word 的 nibble 0..7 是 `Q[0,0],Q[8,0],Q[0,8],Q[8,8],Q[1,0],Q[9,0],Q[1,8],Q[9,8]`，再加上 K/N tile 的全局起点。lane=5、warp=2：`tc_col=1,tc_row=2`，N 起点是 33；nibble 0 是 Q[tileK+2,tileN+33]，nibble 7 是 Q[tileK+11,tileN+41]。

## 3. 自己写重排

复制 [v6f_marlin_repack_template.cu](../kernels/marlin_from_scratch/v6f_marlin_repack_template.cu) 为 `v6f_marlin_repack.cu`，只填 GPU kernel：利用给出的 block K/N tile 和真实 lane/warp，根据上图从 P 取 8 个 q 并按 nibble 顺序写一个 word。tile 物理起点按 `[K/16,N/64,128]` 行优先定位。

CPU oracle 方向与 GPU 相反：它逐个读取逻辑 `Q[k,n]`，确定该值应该写到哪个 word/nibble；不调用 GPU 算法。测试包括 `(256,128),(128,64),(384,192)` 的逐 word 精确比较。

```bash
cp kernels/marlin_from_scratch/v6f_marlin_repack_template.cu kernels/marlin_from_scratch/v6f_marlin_repack.cu
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo kernels/marlin_from_scratch/v6f_marlin_repack.cu -o /tmp/quant_v6f
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_v6f --dump /tmp/quant_v6f_words.bin
```

`--dump` 仅在固定例通过时写 4096 个 uint32。可选上游对照需完整参考项目和环境，选择空闲 GPU：

```bash
cd ../vllm-from-scratch
source scripts/activate-4090.sh
CUDA_VISIBLE_DEVICES=1 python ../quant-gemm-project/tests/v6f_compare_upstream.py /tmp/quant_v6f_words.bin
cd ../quant-gemm-project
```

2026-11-24 的旧版“连续线程写连续 word”临时参考填充曾通过 3 组 CPU 对照，固定例 4096 个 word 与本机冻结上游 repack 一致。按照当前真实 warp/lane 分工重新验证的结果见下方记录；这些不是你写的结果，测试数据带周期性，后续仍需更多随机/可识别数据。

更新后的临时参考填充在 RTX 4090、CUDA 12.1、SM89 下通过三种形状的 CPU 对照和 memcheck；固定例的 4096 个 word 也再次与本机上游 repack 一致。该结果验证的是测试框架和临时填充，不代表用户尚未填写的代码已通过。
