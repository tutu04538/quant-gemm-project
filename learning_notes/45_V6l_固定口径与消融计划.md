# V6l：参考写回顺序与完整实例的剩余拼图

## 1. 为什么这节先看数值顺序

V6h/i 学的是参考物理 Q/Z/S 到 BF16 B 寄存器；V6j/k 学了相同 B 片段坐标进入 MMA 和四 warp 的 K 分工。它们还是分开的诊断实验：Q/Z/S 的测试输出没有直接接入 V6j/k。下一节 [V6m](46_V6m_参考布局融合四warp.md) 会在一个诊断 kernel 中串联这条路径；shared pipeline、参考归约及完整实例差分仍需继续完成。

固定实例 [write_result](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/marlin_template.h#L1627) 的 `write` 对每两个结果先将 FP32 转为输出 BF16，再在 `has_bias && last` 时用 `__hadd2` 加 BF16 bias。对于本例 group_blocks=8，不走该函数中 `group_blocks==-1` 的 per-column scale 分支。

```text
参考 FP32 部分和归约后 ─→ float2num 转 BF16 ─→ BF16 加 bias ─→ BF16 C
```

这与旧教学练习 `BF16(float_acc+float_bias)` 的舍入顺序不同。该判断针对固定实例的 BF16、group=128、has_bias 且最后一个 slice；其他格式/条件必须另查。实际写回还有 shared 片段重排、跨 block 归约和锁，不是一个独立标量 kernel 就已复现。

## 2. 可手算的反例

```text
acc = 1.00390625 = 1 + 1/256
bias = 0.00390625 = 1/256（BF16 可表示）

先转 BF16：acc 位于 1.0 与 1.0078125 的正中，ties-to-even → 1.0
再 BF16 加 bias：又处于这两个数中间，ties-to-even → 1.0（0x3f80）

若先 FP32 相加：1.0078125，转 BF16 为 0x3f81
```

所以只拿容差较宽的最终 C 测试可能看不出顺序错误。

## 3. 动手验证一个元素的 epilogue

复制 [v6l_bias_rounding_template.cu](../kernels/marlin_from_scratch/v6l_bias_rounding_template.cu)，每线程处理一个 float acc 和一个 BF16 bias：先用 `__float2bfloat16_rn` 转 acc，再用 BF16 `__hadd` 加 bias。host 预设多个值，逐 BF16 位比较参考次序，并输出两种顺序不同的数量。

```bash
cp kernels/marlin_from_scratch/v6l_bias_rounding_template.cu kernels/marlin_from_scratch/v6l_bias_rounding.cu
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo kernels/marlin_from_scratch/v6l_bias_rounding.cu -o /tmp/quant_v6l_marlin
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_v6l_marlin
```

临时参考填充在 RTX 4090、CUDA 12.1、SM89 的 5 个 case 通过，两个 case 的两种顺序产生不同 BF16 位；不是你的实现成绩，也不等同于真实参考 kernel 的完整 epilogue 验证。

## 4. 之后必须连接并验收的路径

```text
V6f/g：参考格式 Q/Z/S
   ↓
V6h/i：该格式 → 每 lane B 片段（当前为诊断 kernel）
   ↓ V6m：在同一 kernel 中把这些片段连接到下面的 MMA（当前是待完成练习）
V6j/k：片段 → MMA → warp 部分和（当前 B 由 host 构造）
   ↓ 尚未完成：参考 thread_block_reduce 的 shared 布局和阶段
固定实例 block 部分和
   ↓ 尚未完成：参考 slice 调度、C_tmp / locks、最后一个 slice
参考 BF16 舍入与 bias → shared 输出重排 → global C
```

V7 按参考 `cp.async` 的实际 `fence`/`wait`、stage 复用与 block 同步构建时间线；V8 按参考 `global_reduce_fp32`、`barrier_acquire/release` 与固定实例的 slice 顺序实现/验证；V9 做接口、数值和公平性能验收。源码来源与许可证需保留。只有这些步骤与具体测试完成后，才能说理解或复现了**这个固定分支**；要覆盖整个模板的全部量化类型、架构和配置，还需另行分析和验证。

对性能：使用同一逻辑 Q/Z/S/A/bias 和 dtype，固定 GPU/构建、阈值、warmup、重复、计时边界；分别测重排、稳态和端到端。无 profiler 计数器权限时如实记录，不凭时延推测 DRAM 流量。
