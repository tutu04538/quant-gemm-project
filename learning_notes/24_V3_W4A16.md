# V3：从 4 bit 权重到朴素 W4A16 GEMM

## 1. 目标和这节做什么

我们要写一个能验证数据布局和数值语义的 W4A16 GEMM：A 是 BF16，权重以 4 bit 存放，按需解码为 BF16，乘加使用 FP32，输出 FP32。先完成 `decode_weight`，检查每个权重；再让每个线程负责一个输出元素。**本节不追求性能，不使用 Tensor Core，也不声称兼容 Marlin 的物理布局。**

```text
V3a：定义 Q、packed、zero、scale 的契约（阅读和手算）
V3b：理解数学参考和 BF16 舍入参考（阅读和手算）
V3c：写一个权重的 GPU 解码函数（模板 TODO 1～3）
V3d：写朴素 W4A16 GEMM（模板 TODO 4～6）
V3e：理解本实验的形状与接口边界（本节不做通用接口）
```

后续已按要求实现一个受限、同步的 V3e 调用入口，详见 [V3e：接口检查与拒绝](25_V3e_接口检查与拒绝.md)；它不改变本节原始 kernel。

一个模板包含两个 kernel：`decode_all` 是诊断工具，用于检查每个解码结果；`w4a16_gemm` 是实际 GEMM，它只在 K 循环中按需解码，**不先构造完整 W**。测试程序为了逐元素验证会额外分配完整 W；这不是 GEMM 的热路径。

## 2. 输入、输出和限制

固定 group size = 128，举例 M=16、K=256、N=128：

```text
A：BF16       [M,K]       连续行优先
Q：逻辑 uint4 [K,N]       每个值 0～15，是概念上的原始权重
P：uint32     [K/8,N]     Q 沿 K 轴每 8 个打包，连续行优先
Z：uint8      [K/128,N]   每项取 0～15，本节不对 zero 打包
S：BF16       [K/128,N]   每项一个 scale
C：float32    [M,N]       连续行优先，无 bias
```

K 必须为正且能被 128 整除，M、N 均为正；N 不要求 8 或 16 对齐，越界输出线程直接返回。这里无 padding、无 stride 参数、无 act-order、无 bias。示例测试使用有限的非负 scale；不设计异常值输入的语义。这个独立教学程序由测试代码构造合法的 device 缓冲，**没有实现供外部调用的参数校验接口**，不能声称已覆盖非法 dtype、device、stride、空输入、别名、stream 或并发，也不构成路线 V3e 的完整通用接口验收。

对 `g = k / 128`（整数除法向下取整），本节的数值约定：

```text
w_math  = float(int(Q[k,n]) - int(Z[g,n])) * float(S[g,n])
w_bf16  = BF16_round_to_nearest_even(w_math)
C[m,n]  = 按 k 从小到大累加 float(A[m,k]) * float(w_bf16)，FP32 输出
```

S 已经是 BF16；`float(S)` 是把该 BF16 值准确转换为 FP32。`w_bf16` 先舍入一次，然后用于乘法。本实验的参考使用 FP32 `fma` 从小到大累加；实现可使用 FP32 乘加，测试容差见后文。这个明确约定不代表 Marlin 每条路径都有相同的舍入顺序。

## 3. 画出 Q 到 packed 的对应关系

本节自定义沿 K 打包，**不是直接拿 Marlin repack 后的 qweight 来用**。一个 32 位 word 有 8 个 4 位 nibble；同一列 n 内 K 从小到大，对应从低 4 位到高 4 位：

```text
逻辑 Q（只画第 n 列）                    物理 P（uint32 数组）
Q[ 0,n] = 0 ─┐                        P[0,n] = 0x76543210
Q[ 1,n] = 1 ─┤                           最高位                  最低位
Q[ 2,n] = 2 ─┤                        bit 31                       bit 0
Q[ 3,n] = 3 ─┤                           [7][6][5][4][3][2][1][0]
Q[ 4,n] = 4 ─┤                            ↑                    ↑
Q[ 5,n] = 5 ─┤                          Q[7,n]              Q[0,n]
Q[ 6,n] = 6 ─┤
Q[ 7,n] = 7 ─┘
Q[ 8,n]      ──────────────────────→ P[1,n] 的最低 4 位
 ...
Q[127,n] ─→ P[15,n] 的最高 4 位，属于 group 0
Q[128,n] ─→ P[16,n] 的最低 4 位，属于 group 1
```

上图的 `0x76543210` 是一个 32 bit 数值按十六进制写出来的样子，不是在描述内存中逐字节显示的先后顺序。P 的每行有 N 个 `uint32`，列 n 的相邻两个 K word 之间隔 N 个 `uint32`，并非一定相邻：

```text
物理线性数组：P[0,0], P[0,1], ... P[0,N-1], P[1,0], ...
                  一个 word 行有 N 个 uint32
```

手算：取 `P[0,n]=0x76543210` 中的 `Q[3,n]`。右移 `4×3=12` 位，最低 4 位变成 3，再与二进制 `1111`（即 `0xF`）按位与，得到 3。模板用 `uint32_t`，右移是无符号右移；`& 0xFu` 保留最低四位。

用整数除法和取余可以判断：第几个 word 是 `k / 8`，word 内第几个 nibble 是 `k % 8`。以行优先 `P[row,n]` 的线性地址为 `row*N+n`。这些是定位的提示，具体代码请你写。

## 4. group、zero、scale 和手算

```text
          K 轴                         每一列各有自己的 Z 和 S
     0 ────────── 127  ──→ group 0 ──→ Z[0,n], S[0,n]
   128 ────────── 255  ──→ group 1 ──→ Z[1,n], S[1,n]
```

例一：`Q[3,0]=3`，`Z[0,0]=7`，`S[0,0]=0.25`。整数差为 -4，权重数学值为 -1；-1 可由 BF16 精确表示，所以 `w_bf16=-1`。假设 `A[2,3]=2`，该 K 项对 `C[2,0]` 的贡献为 -2。完整 C 还要累加其余 K 项。

例二：`Q[128,0]=11`，`Z[1,0]=7`，`S[1,0]=0.25`，则权重是 1。这里必须读 **group 1** 的 Z/S，而不是因为 word 的 nibble 编号重新变成 0 就取 group 0。

`q` 与 zero 是无符号存储：务必先转换到 `int` 再减法。例如 3−7 应得到 -4；如果按无符号规则先减，结果会变成很大的正数。`static_cast<int>(q)` 或 `int(q)` 都是 C++ 的显式类型转换。

## 5. 为什么需要两种参考

```text
同一原始逻辑 Q/Z/S 和 BF16 A
        ├─ 数学参考：w_math 不转 BF16 → FP32 FMA → C_math
        └─ 本版语义：w_math 转 BF16    → FP32 FMA → C_expected
                                                   ↑
                                           GPU 输出与它比较
```

当 scale 是 0.25，差值是整数时，许多权重可精确转为 BF16；当 scale 为 0.1 等值时，输入 scale 已经经历 BF16 舍入，乘出来的 `w_math` 也可能无法精确表示为 BF16，因此 `C_math` 与 `C_expected` 可能不同。测试会报告两者的最大差值，用于观察**权重转换为 BF16**这一步的影响，并不是 GPU 相对误差。

CPU 参考直接访问原始逻辑 `Q[k,n]`，不调用 GPU 解码或从 P 提取；因此 pack 和解码不能只靠互相抵消通过。测试还断言固定的 `P[0,0] == 0x76543210`，让打包方向有独立手算锚点。逐个 BF16 权重要求与参考相等；C 的阈值预先固定为 `abs(actual-expected) <= 0.0001 + 0.00001 * abs(expected)`，非有限输出必定失败。这只适用于本模板的测试数据，不是通用误差保证。

## 6. block、warp、lane 与内存流动

`w4a16_gemm` 用二维 block `(16,16)`，即 256 条线程 = 8 个 warp。每个 block 负责最多 16×16 个 C 元素：

```text
C [M,N]                     block (bx,by) 的 16×16 输出 tile
        N →                         col = bx*16 ... bx*16+15
    ┌────────────┐                ┌────────────────────────┐
 M  │   tile     │                │ ty=0   tx=0 ... tx=15 │
 ↓  │   ...      │                │ ty=1   tx=0 ... tx=15 │
    └────────────┘                │ ...                    │
                                  │ ty=15  tx=0 ... tx=15 │
                                  └────────────────────────┘
```

CUDA 将二维 block 线性化：`tid = threadIdx.y*16 + threadIdx.x`；`warp=tid/32`、`lane=tid%32`。所以 warp 0 的 lane 0～15 是 `(ty=0,tx=0～15)`，lane 16～31 是 `(ty=1,tx=0～15)`；warp 1 对应 ty=2、3，以此类推。每条有效线程自己遍历全部 K：

```text
该线程负责 C[row,col]，寄存器里维护一个 float 累加值
  for k = 0 ... K-1:
    global A[row,k] ──→ BF16 → float ───────────────┐
    global P[k/8,col] → 取 4 bit q                   │
    global Z[k/128,col], S[k/128,col] → 解码 → BF16 → float
                                                     ↓
                                               FP32 乘加
  最后写 global C[row,col]
```

相邻 lane 可能重复读同一个 A、重复读相同的 packed word；这版优先建立正确性，不假设这些读取都实际落到 DRAM，也不假设访问一定高效。没有 shared memory，也没有线程间屏障。`decode_all` 是另一个一维 launch，每条线程处理一个逻辑 `(k,n)`，与 GEMM 的线程分配不同。
