# V6h：固定 Marlin 实例的 packed Q 如何进入 BF16 寄存器

## 1. 目标与范围

继续 V6f/g 的**参考物理布局**。这节对固定实例的四个有效 block、全部 warp/lane、每 warp 两个 K16 step、每个 lane 的四个 packed Q word，复现 `dequant_data` 的第一步：用 `lop3` 构造带 128 偏置的 BF16x2 位模式。下节再接真实物理 Z/S。

固定例 A BF16 `[16,256]`，逻辑 Q uint4 `[256,128]`，K group=128；参考 repacked Q 物理形状 `[16,256]` uint32。为了能观察所有中间结果，本节的诊断 kernel **直接从已重排的 global Q 读取**；参考实例实际是 global→shared→`frag_b_quant`，还包含 pipeline，因此本节只验证索引与编码，不宣称复现搬运/流水线，也没有在上游 kernel 内插桩。

## 2. block、warp、lane、word 和两次解码

```text
block 0：N 0..63, K 0..127    block 1：N 0..63, K 128..255
block 2：N 64..127,K 0..127   block 3：N 64..127,K 128..255

每 block 128 threads = 4 warp；每 warp 处理 32 个 K
每 lane 每个 K16 step 读一个 int4 = 4 个 uint32：

             word j=0          j=1          j=2          j=3
           ┌───────────┬───────────┬───────────┬───────────┐
某 lane    │8 个 nibble│8 个 nibble│8 个 nibble│8 个 nibble│
           └───────────┴───────────┴───────────┴───────────┘
```

令 `nr=block/2,kr=block%2,w=warp,l=lane,s=step,j=word编号`。对应 Q 的**物理 uint32 下标**：

```text
row = 8*kr + 2*w + s
col = 128*nr + 4*l + j
word = repacked[row*256 + col]
```

例如 block0、warp0、lane0、step0、j0 是物理 `[0,0]`；这个 word 低→高 nibble 是逻辑：

```text
 Q[0,0] Q[8,0] Q[0,8] Q[8,8] Q[1,0] Q[9,0] Q[1,8] Q[9,8]
```

word 中 q0、q4 恰好属于同一列的相邻 K，q1、q5 也是一对。**这是重排的用处**：解码后每个 BF16x2 对齐该 lane 的 MMA B fragment，而不是把同一行的 8 列放在一起。

这里的“对齐”指**元素的归属和顺序符合 MMA 输入寄存器的要求**，不是指地址对齐。以 warp 0 的 lane 5、一个 K=16、N=16 的小块为例：`g = 5 / 4 = 1`，`t = 5 % 4 = 1`。这个 lane 的一个 packed word 从低位到高位保存：

```text
位置        q0       q1        q2       q3       q4       q5        q6       q7
逻辑 Q    [2,1]   [10,1]    [2,9]   [10,9]    [3,1]   [11,1]    [3,9]   [11,9]
            │         │        │        │         │        │         │        │
            └─────────┼────────┼────────┼─────────┘        │         │        │
                      └────────┼────────┼──────────────────┘         │        │
                               └────────┼────────────────────────────┘        │
                                        └─────────────────────────────────────┘
配对      (q0,q4)    (q1,q5)  (q2,q6)  (q3,q7)
```

这四对分别对应以下逻辑位置；减去 zero 并乘上 scale 后，才能得到真正输入 MMA 的 BF16 权重 `W`：

```text
第一条 MMA，处理 N 的前 8 列：
  lane 5 的 B 寄存器 0 = (W[ 2,1], W[ 3,1])  ← q0、q4
  lane 5 的 B 寄存器 1 = (W[10,1], W[11,1])  ← q1、q5

第二条 MMA，处理 N 的后 8 列：
  lane 5 的 B 寄存器 0 = (W[ 2,9], W[ 3,9])  ← q2、q6
  lane 5 的 B 寄存器 1 = (W[10,9], W[11,9])  ← q3、q7
```

每个寄存器是一个 BF16x2：括号中的前一个值在低 16 位，后一个值在高 16 位。比如第一对都来自逻辑列 1，K 分别为 2 和 3。重排把这些**逻辑上不一定相邻存储**的量化值放入同一个 word，并安排到便于解码成所需 BF16x2 的位位置；它并没有改变逻辑矩阵的坐标或数值。下节的位运算会先构造带 `128` 偏置的 BF16，之后还需要减 zero、乘 scale，不能把刚构造的值直接当作最终权重。

## 3. `lop3` 和 `0x4300` 逐步手算

参考 [dequant.h 的 BF16 U4 特化](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/dequant.h#L174)与 [matmul 中两次 dequant_data](../third_party/vllm_marlin/minivllm/csrc/quantization/marlin/marlin_template.h#L1222)：

```text
MASK = 0x000f000f        EX = 0x43004300
raw0 = (word       & MASK) | EX   → q0, q4  → frag_b0[0]
raw1 = ((word>>4)  & MASK) | EX   → q1, q5  → frag_b0[1]
raw2 = ((word>>8)  & MASK) | EX   → q2, q6  → frag_b1[0]
raw3 = ((word>>12) & MASK) | EX   → q3, q7  → frag_b1[1]
```

每个 raw 的低/高 16 bit 是两个 BF16；`0x4300` 表示 128，`0x4300|q` 表示 128+q。若 `word=0x76543210`，raw0 的低 16 bit 为 `0x4300`（128+0），高 16 bit 为 `0x4304`（128+4），所以 raw0=`0x43044300`。之后 Q 和 Z 都带 128，做 BF16 减法时偏置抵消。

`lop3.b32` 对三个 32-bit 输入逐 bit 计算逻辑函数。参考代码用立即数 `0xea` 表达 `(a&b)|c`；在内联 PTX 中输出使用 `"=r"`，输入使用 `"r"`。你无需自己推导所有真值表，但要知道 `0xea` 是编译期立即数，不是被读取的地址。

## 4. 实践与验收

复制 [v6h_marlin_quant_template.cu](../kernels/marlin_from_scratch/v6h_marlin_quant_template.cu) 为 `v6h_marlin_quant.cu`。实现 `lop3_extract` 并按上述顺序写 4 个 raw pair；host 已按原始逻辑 Q 的反向映射独立构造 repacked 输入，另从逻辑 Q 直接构造期望 raw bit，不读取你的解码结果。

```bash
cp kernels/marlin_from_scratch/v6h_marlin_quant_template.cu kernels/marlin_from_scratch/v6h_marlin_quant.cu
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo kernels/marlin_from_scratch/v6h_marlin_quant.cu -o /tmp/quant_v6h_marlin
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_v6h_marlin
```

3 个随机 seed，每组比较 4 blocks×4 warps×32 lanes×2 steps×4 words×4 pairs，每个 32 bit 必须精确一致。临时参考填充三组通过，memcheck/racecheck/synccheck 未报告错误或危害；不代表你的代码已通过，也不等于上游 GEMM 内部寄存器已捕获。
