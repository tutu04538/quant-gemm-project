# V6o：去除 FP32 诊断写入的优化实验

## 1. 要验证什么

V6o 完整写回前会把 FP32 部分和写入 `diagnostic[16,128]`，供课程逐元素验证。生产输出只需要 BF16 C。本实验比较：**关闭这一次诊断写入，其他计算、四 block 分工、锁、tmp 和 bias 顺序保持相同**，是否降低该固定例子的 GPU 时间。

源码仍默认执行诊断写入；增加编译开关 `V6O_DISABLE_DIAGNOSTIC` 后，可在编译时去掉这条写入。预处理开关同样关闭测试程序中针对 FP32 diagnostic 的比较并明确打印“未启用”，BF16 输出仍由 CPU 参考校验。优化版不写 diagnostic；它仍保留该指针参数，因此接口未精简。

```text
公共路径：Q/Z/S 解码 → MMA → 四 warp 合并 → 跨 block 合并 → FP32 sum
                                                                  ├─ 原版：写 diagnostic
                                                                  └─ 两版：转 BF16、加 bias、写 C
```

## 2. 固定条件与计时方法

RTX 4090（SM89）；M=16、N=128、K=256、group=128；BF16 A/scale/bias/output、uint4 权重和 zero，包含非精确 scale；初始锁为零。两个 V6o 版本由同一源码、同一 CUDA 12.1 nvcc、同一 `-O2 -arch=sm_89 -lineinfo` 构建，仅用 `-DV6O_DISABLE_DIAGNOSTIC` 改变开关。使用两套大小与布局相同、互不共享的输出及 workspace。参考 Marlin 输入来自同一逻辑输入，构建工具链为 CUDA 12.9；时间只作参考基线。

原版、优化版和参考 Marlin 都预热 50 次；分别捕获 128 次调用的 CUDA Graph，预热 graph 5 次。36 个 batch 轮换六种三者执行顺序；每个 batch 用 CUDA Event 记录一次 graph，再除以 128。以下为同一轮交替实验的中位数，排除 repack、输入准备及 host 调用；包含各 kernel 中的锁、临时缓冲和正常写回。

## 3. 正确性

两种编译版本分别运行 V6o 原有 3 seed × 3 输入模式的 CPU 对照，每组连续启动 5 次并检查锁复位：BF16 输出 0 错误且逐位差异 0；启用 diagnostic 的原版 FP32 部分和也 0 错误。无诊断版本明确不声称 FP32 中间值已被直接比较。

性能测试的同一份输入中，两版 BF16 输出逐位一致，与参考 Marlin 的 2048 个 BF16 输出也逐位一致；三者与独立逻辑 Q/Z/S 的 oracle 最大绝对差为 0。禁用版 diagnostic 保持初始 NaN，确认没有写；两个锁数组均复位。比较阈值 `atol=0.125, rtol=0.02`，逐位相同仅适用于本次输入。

无诊断版本通过 memcheck、racecheck、synccheck（0 错误或危害）；这些检查不证明全局锁在全部调度下正确。

## 4. 实测结果

| 版本 | GPU 时间中位数 | batch 最小～最大 | 相对原版耗时 |
|---|---:|---:|---:|
| V6o，写诊断 | 7.864 μs | 7.856～7.888 μs | 100% |
| V6o，关闭诊断 | 7.232 μs | 7.216～7.248 μs | 91.96% |
| 参考 Marlin | 3.263 μs | 3.248～3.272 μs | — |

在这个测量口径和输入下，关闭写入减少约 **0.632 μs（8.0%）**；优化版仍约为参考 Marlin 时间的 **2.22 倍**。这个差异不能全部解释为“8 KiB 写入的带宽”：删掉写入也会改变编译后的指令和寄存器分配。

`ptxas -v` 中 `v6o_compute` 的静态资源：

| 版本 | 每线程寄存器 | 每 block shared | stack frame | spill load/store |
|---|---:|---:|---:|---:|
| 写诊断 | 95 | 18432 字节 | 0 | 0 / 0 |
| 不写诊断 | 80 | 18432 字节 | 0 | 0 / 0 |

这不是 profiler 采集的运行时占用率；无 spill 也不代表没有其他 local memory 操作。当前没有硬件计数器证据，不能判断提速中寄存器变化、指令调度和写入量各占多少，也不能据此断定剩余瓶颈。

## 5. 复现

```bash
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo -Xptxas=-v -shared -Xcompiler -fPIC benchmarks/v6o_benchmark_wrapper.cu -o /tmp/v6o_diag.so 2> /tmp/v6o_diag_ptxas.log
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo -Xptxas=-v -DV6O_DISABLE_DIAGNOSTIC -shared -Xcompiler -fPIC benchmarks/v6o_benchmark_wrapper.cu -o /tmp/v6o_nodiag.so 2> /tmp/v6o_nodiag_ptxas.log
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo -DV6O_DISABLE_DIAGNOSTIC kernels/marlin_from_scratch/v6o_four_block_template.cu -o /tmp/v6o_nodiag_test
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/v6o_nodiag_test
CUDA_VISIBLE_DEVICES=1 CUDA_HOME=/data/syh/infra/cuda-12.9 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 MAX_JOBS=2 TORCH_CUDA_ARCH_LIST=8.9 ../vllm-from-scratch/.venv/bin/python benchmarks/benchmark_v6o_diagnostic.py
```
