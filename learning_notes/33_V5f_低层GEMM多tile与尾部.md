# V5f：把低层 GEMM 扩展到多个输出 tile

先完成并验证 [V5e](32_V5e_低层MMA完整K循环.md)。本节继续修改同一个 `v5ef_lowlevel.cu`，只补 M/N 边界与多 block；K 仍限定为 128 的正整数倍，因此每轮 K=16 都完整，不处理 K 尾部。

## 1. 要解决什么问题

V5e 的一个 warp 算 C 的 16×8。现在支持正数 M/N，网格用向上取整：

```text
grid.x = ceil(N/8), grid.y = ceil(M/16)
block = 32 threads = 一个 warp
block(bx,by) 负责 row0=by*16、col0=bx*8 开始的 C tile
```

例如 M=17、N=19：grid=(3,2)。

```text
                N: 0..7    8..15    16..18
rows 0..15       (0,0)      (1,0)      (2,0)
row  16          (0,1)      (1,1)      (2,1)
                                           ↑
                         实际只有 1 行 × 3 列有效 C
```

每个 block 仍然运行完整 warp 和 16×8 MMA。不能让输出越界的 lane 提前退出，因为它可能负责加载别的 lane 的输入，也必须参加同步、`ldmatrix` 和 `mma.sync`。

## 2. 为边缘 tile 补零

对 block(2,1)：row0=16、col0=16。

```text
shared as[16,16]                shared bs[16,8]
  第 0 行读取 A[16,k]              前 3 列读取 W[k,16..18]
  第 1..15 行补 0                  后 5 列补 0
                 ↓  全 warp ldmatrix + MMA
      得到完整 16×8 的寄存器输出，但只写有效的 1×3 部分
```

对 A，判断 `row0+r<M` 才能读 global；否则写 BF16 0。对 B，判断 `col0+n<N` 才能读 packed、Z、S；否则写 BF16 0。边缘判断必须发生在读取之前；无效地址不能先读出再丢弃。K 是 128 倍数且 base 以 16 步进，因此在本节契约中每轮 k 都有效。

## 3. lane 的 4 个结果分别检查

令 `g=lane/4,t=lane%4`，实际输出坐标：

```text
acc[0] → (row0+g,   col0+2t)
acc[1] → (row0+g,   col0+2t+1)
acc[2] → (row0+g+8, col0+2t)
acc[3] → (row0+g+8, col0+2t+1)
```

例如边缘 block(2,1) 的 lane 1，g=0,t=1：四个坐标是 `(16,18)`、`(16,19)`、`(24,18)`、`(24,19)`；只有第一个有效。每个 acc 单独判断行和列，再写 global C。

## 4. 你来完成

在已完成 V5e 的同一个文件中补 TODO 6 和 8：

1. 每轮 A/B 的 shared 填充检查 M/N，无效位置写零。
2. 每 lane 输出的 4 个坐标分别检查 M 和 N；仅有效输出写回。
3. 不改 K 循环的 acc 生命周期、完整 warp 参与和同步顺序。

编译命令同 V5e，然后运行：

```bash
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_v5ef --f
```

`--f` 覆盖 `(16,8,256)`、`(1,1,128)`、`(17,19,256)`、`(31,33,384)`、`(16,128,256)`，小整数与 BF16 小数各一组。CPU 参考和容差与 V5e 相同；K=384 跨三个 group，17×19 和 31×33 检查 M/N 尾部。测试仅覆盖声明的连续正尺寸，不提供非法输入检查或并发接口。

2026-11-23 临时参考填充的 10 组测试全部通过，最大误差 `9.53674e-6`；memcheck、racecheck、synccheck 均无错误或危害。这是测试框架与临时实现的证据，不代表用户代码已经通过。V5f 完成后可以与 V5b/c 使用相同输入做正确性和性能对比；不能预先断言哪条更快。
