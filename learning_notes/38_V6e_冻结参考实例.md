# V6e：冻结参考实例与比较证据

## 1. 先确定我们要复现什么

从这一节起，以已实际运行过的固定分支作为目标，先验证输入准备、权重与量化参数，再逐步研究片段、计算和协作。V6c 已通过，但它的教学 R 布局和 FP32 输出不与参考接口兼容。

```text
逻辑输入（同一份 Q/Z/S/A/bias）
   ├→ 现有 V5/V6 教学布局 → 教学 GEMM → FP32 C（无 bias）
   └→ 参考路径：standard → Q/Z/S 分别重排 → Marlin → BF16 C（含 bias）
```

这不是性能对比图：两边 dtype/bias、计算和重排不同，必须先对齐语义，之后才能制定公平的比较。

## 2. 固定输入、调用和历史证据

```text
M=16, K=256, N=128；group=128，4 bit unsigned Q，0..15
A BF16 [16,256]；逻辑 Q [256,128]
Z [2,128]（逻辑 0..15）；S BF16 [2,128]；bias BF16 [128]
无 act-order；输出 C BF16 [16,128]；无 K/N padding
```

数学语义 `C= A @ ((Q-Z)*S) + bias`；实际 BF16 中间操作和输出舍入须按分支核对。历史实测（2026-11-21）看到 128 block、每 block 128 threads、4 warp、thread M/N/K blocks=1/4/8、stages=4；该实例 `has_bias=true,use_atomic_add=false,use_fp32_reduce=true`。历史输入与输出比较通过 `rtol=0.02,atol=0.05`，max abs≈0.01533；这不是性能测试。完整 [记录](Marlin固定例子_实测记录.md)、[trace](Marlin固定例子_profiler.json)、[实例图解](12_Marlin固定实例_启动布局与反量化.md)。

注意证据边界：launch 是历史 profiler 捕获；内部 block/warp/lane 是源码推导；先前对 packed Q 和量化参数做过映射核对，但没有逐 lane 捕获 GEMM 中的实际寄存器。历史测试没有保存输入 tensor，跨软件版本 seed 重建不保证 bitwise 一致。

参考项目 HEAD `3ae5eefb0ab3eecdbc75c16b7d7e733c5116aec0`，上游 Marlin CUDA 源自 vLLM `2cf0a6915ce544dc493a0990f2ea38d81601128a`；许可证及快照边界见 [来源说明](../third_party/vllm_marlin/README.md)。注意参考项目其他测试、完整包和环境仍位于 `../vllm-from-scratch`，不在本仓库快照内。

## 3. 一次 tile 的内存和线程路径

```text
逻辑 Q/Z/S                       准备阶段
     ├→ standard P[K/8,N] ─→ Marlin qweight repack
     ├→ Z[g,n] ────────────→ 置换 + 4-bit pack
     └→ S[g,n] ────────────→ 置换 BF16
                                 ↓
  kernel：128 threads/block，4 warp（具体 block 工作量见历史实例图）
     global packed Q/S/Z → shared pipeline → lane 的寄存器片段
                                               ↓ BF16 解码与 MMA
                        部分和 → 参考归约/epilogue → BF16 C
```

本次需要先把 Q、S、Z **分别**对照，不能将一种 permutation 套给所有张量。接下来 V6f 验证 Q；V6g 验证 S/Z；V6h 再观察一个 packed word 的 BF16x2。V6i～k 首先搭教学桥梁，尚未等于固定实例全部 fragment/流水线/归约。

## 4. 本次新证据

2026-11-24 在 RTX 4090 和本机参考项目环境中，用固定 K=256/N=128、无 perm 的相同逻辑 Q，临时填写的 V6f GPU repack 输出与参考 `gptq_marlin_repack` 的 **4096 个 uint32 word 全部相等**；另以独立 CPU 反向映射检查 3 组形状。V6g 的 CPU 反向映射与参考 Python `marlin_permute_scales` / `marlin_zero_points` 在 K=256/N=128 上逐 BF16 位/逐 zero word 一致。可复现脚本：[Q 对照](../tests/v6f_compare_upstream.py)、[S/Z 对照](../tests/v6g_compare_upstream.py)。

这些结果验证了**临时参考填充及特定数据**，不是你尚未完成的练习结果；S/Z 上游对照此时验证的是 CPU 映射，尚不是用户的 GPU 输出与上游直接对照。测试依赖本机完整参考项目与其 CUDA/PyTorch 环境；缺少依赖时仍可做独立 CPU 对照，但不能宣称跑过上游差分。
