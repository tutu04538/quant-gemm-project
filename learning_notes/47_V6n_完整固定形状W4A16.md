# V6n：从 V6m 的部分和到完整固定形状输出

## 1. 本节解决的问题

V6m 的两个 block 各处理一个 K group，且只处理 N=0..63；最终只写出每个 warp 的部分和。本节在你完成的 V6m 基础上，实现一个能写出完整 `C[16,128]` 的单 kernel。完整指**本节固定形状与数据契约内的完整输出**，不指完整通用 Marlin。

- 输入：A BF16 `[16,256]`；逻辑 Q uint4 `[256,128]`、整数 zero `[2,128]`、BF16 scale `[2,128]`；BF16 bias `[128]`。
- group size 为 128。每个逻辑权重先按 BF16 运算得到 `W[k,n] = BF16((Q[k,n] - Z[k/128,n]) * S[k/128,n])`。
- Q 预先重排成物理 `[16,256]` uint32，每 word 从低位到高位存 8 个 nibble；Z 物理 `[2,16]` uint32，S 物理 `[2,128]` BF16，均沿用 V6f/g 的固定参考布局。无 padding、无 act-order。
- FP32 累加和按本例四 warp 顺序相加，转换 BF16 后再做 BF16 bias 加法。输出 BF16 `[16,128]`；另写 FP32 `diagnostic` 供测试，属于诊断开销。

完整代码和测试在 [v6n_full_gemm_template.cu](../kernels/marlin_from_scratch/v6n_full_gemm_template.cu)。它是**已填写的模板**：按你的要求由助手基于 V6m 实现；不覆盖你的 V6m 代码。

## 2. block 和 warp 分工

```text
CUDA grid：2 blocks，每 block 128 threads = 4 warps × 32 lanes

                  输出 N 0..63                 输出 N 64..127
              ┌──────────────────┐           ┌──────────────────┐
blockIdx.x    │ block 0 (nr=0)   │           │ block 1 (nr=1)   │
              │ C 的左半 16×64   │           │ C 的右半 16×64   │
              └──────────────────┘           └──────────────────┘

每个 block 内：
           group 0 (K 0..127)       group 1 (K 128..255)
warp 0     K 0..31                  K 128..159
warp 1     K 32..63                 K 160..191
warp 2     K 64..95                 K 192..223
warp 3     K 96..127                K 224..255

每个 warp 的每一段各有两个 K16 step；同一 lane 的 acc 跨 group 累加。
四 warp 对同一输出 tile 的部分和 → shared part[4][16][64]
  → __syncthreads() → warp 0 合并 → BF16 舍入 → 加 BF16 bias → global C
```

同一输出元素只由所属 N tile 的 block 写入，不需要跨 block 合并。此调度是本节教学设计，**不是参考 Marlin 的 slice 调度**。

## 3. 从 V6m 扩展两个 N tile

令 `nr=blockIdx.x`、`kr=0/1`、`g=lane/4`，仍按 V6i 生成四个 BF16x2。下列坐标是物理布局，不是逻辑 Q 的 K/N：

```text
Qphys[8*kr + 2*warp + step, 128*nr + 4*lane + j]
Zphys[kr, 8*nr + g]
Sphys[kr, 64*nr + 8*g + 2*j] 和紧随的下一个值
```

例如 `nr=1, kr=1, warp=0, lane=5, step=0, j=0`：

```text
g = 1，Qphys[8,148]       （148 = 128 + 4×5）
Zphys[1,9]                （9 = 8 + 1）
Sphys[1,72]、Sphys[1,73]  （72 = 64 + 8×1）
```

对应逻辑 Q 的两列是 `n=65` 和 `n=73`，K 对应 130/131 与 138/139；不能把物理列 148 当作逻辑列。A 的行步长仍是 256，group 起始 K 是 `128*kr`。

## 4. K group、shared 和 BF16 写回

`acc[4][2][4]` 在两个 group 循环外清零：同一个 warp 在 group 0 和 group 1 的结果累加到同一组 FP32 寄存器。每个 warp 将它的 16×64 部分和写到 `part[warp]`；`__syncthreads()` 等待全部 128 个线程写入。warp 0 的 32 条 lane 按线性位置、步长 32 分配输出，每人读取四份 partial 后相加。

```text
寄存器 acc → shared part[warp][m][local_n]
           → 4 warp 的 FP32 和 → diagnostic[m,n]
           → __float2bfloat16_rn → __hadd(bias[n]) → C[m,n]
```

本节先在每 warp 中串行累加两个 group，再按 warp 0、1、2、3 合并。浮点加法顺序影响舍入；参考 Marlin 的 block/slice 归约顺序不同，因此本节不能宣称与参考最终输出逐位一致。

## 5. 编译、测试与结果

```bash
/usr/local/cuda-12.1/bin/nvcc -arch=sm_89 -O2 -lineinfo kernels/marlin_from_scratch/v6n_full_gemm_template.cu -o /tmp/quant_v6n_full
nvidia-smi
CUDA_VISIBLE_DEVICES=1 /tmp/quant_v6n_full
CUDA_VISIBLE_DEVICES=1 /usr/local/cuda-12.1/compute-sanitizer/compute-sanitizer --tool memcheck --error-exitcode 99 /tmp/quant_v6n_full
```

CPU 测试从逻辑 Q/Z/S 坐标独立计算 BF16 反量化权重，按本 kernel 的 warp/group 次序形成 FP32 参考，再按 BF16 先舍入后加 bias 生成输出参考；不使用 GPU 的 repacked 内容解包生成参考。测试在全部 16×128 坐标逐元素比较，覆盖 N=63/64、K group 127/128：3 个 seed × 3 模式，包括随机 Q/Z、0/15 极值、零 bias 和含 0.1/0.7 的 BF16 scale。FP32 阈值 `atol=0.002, rtol=0.0001`；BF16 输出阈值 `atol=0.002, rtol=0.01`，另外统计逐位差异。

2026-11-25 在 RTX 4090、CUDA 12.1、SM89：9 组测试均 FP32 错误 0、最大绝对误差 0、BF16 容差错误 0、逐位不同 0；memcheck、racecheck、synccheck 均无报告。这些是此输入范围和本 CPU 参考下的实测，不证明所有浮点输入均逐位一致，也不是与上游 kernel 的差分或性能测试。
