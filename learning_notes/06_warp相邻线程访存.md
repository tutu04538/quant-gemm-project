# 第 6 节：warp 内相邻线程的访存

## 目标与输入

用上一节的转置，观察同一个 warp 中相邻线程访问的元素是否相邻。输入 `A` 是 `4 × 32` 的 `float` 矩阵，输出 `B` 是 `32 × 4`；两者按行连续存储。每个线程负责一个 `A[row,col] → B[col,row]`。

本节只记录**元素索引**，不测性能，也不根据索引直接声称某个具体事务数。

## 线程与内存流动

```text
grid：4 个 block；block：32 个线程，即一个完整 warp
block 0 → 输入第 0 行；block 1 → 输入第 1 行；以此类推

block 0 中：              A 的元素索引          B 的元素索引
lane 0  → A[0,0] → B[0,0]      0                     0
lane 1  → A[0,1] → B[1,0]      1                     4
lane 2  → A[0,2] → B[2,0]      2                     8
lane 3  → A[0,3] → B[3,0]      3                    12
...
lane 31 → A[0,31] → B[31,0]   31                   124
```

GPU 访问 global memory 时，同一 warp 的线程发出的访问可由硬件合并处理。相邻线程访问相邻位置通常有利于减少所需的内存事务；具体还取决于地址对齐、访问大小、硬件和有效线程。每个 `float` 在本例占 4 字节，上图仍然显示**元素索引**，要换算字节偏移才乘以 4。

这个直接转置中，block 0 相邻 lane 的读取索引相邻，而写入索引相差 4 个元素。另一个形状的步长可能不同；仅凭此图不能断言本例的运行时间或实际事务数。之后会用 shared memory 研究另一种组织方式。

## 手算

block 0 的 lane 2 负责 `A[0,2]`：输入元素索引为 `0 × 32 + 2 = 2`；输出是 `B[2,0]`，输出每行有 4 个元素，所以索引为 `2 × 4 + 0 = 8`。假设每个 `float` 4 字节，它相对 B 起始地址的字节偏移是 `8 × 4 = 32`。

## 练习

打开 [06_template.cu](../kernels/06_template.cu)，填写 kernel 中两个 TODO，记录每个 lane 对应的输入、输出线性元素索引。模板只启动 block 0 对应的一个 warp，CPU 端会验证 32 个结果并打印前 4 个。

想一想：如果输出矩阵每行只有 1 个元素，图中的相邻输出索引会相差多少？这道题只问索引，不问速度。
